# ENG-M13-009 SDK Upgrade Policy and Compatibility

**Status:** IMPLEMENTED_UNAUDITED  
**Task ID:** ENG-M13-009  
**Date:** 2026-11-10

## 1. Pinned Unity Version

**Pinned version: Unity 6000.6.5f1**

- This version MUST NOT be changed without explicit owner approval (Category C gate).
- Upgrading Unity is a breaking-risk operation: IL2CPP code generation, Burst compiler output, Addressables cache format, and package compatibility all depend on the exact editor version.
- Minor patch upgrades (e.g. 6000.6.5f1 → 6000.6.6f1) still require a TASKS.md entry and test evidence.

Enforcement: `SdkVersionPolicy.Validate()` checks `Application.unityVersion` at runtime (Dev/Editor builds only) and throws `InvalidOperationException` on mismatch.

## 2. Android Platform Targets

| Setting          | Value         | Notes                                |
|------------------|---------------|--------------------------------------|
| Min SDK          | 24 (Android 7.0) | Required for Vulkan, modern TLS, and Google Play 64-bit policy |
| Target SDK       | 35 (Android 15)  | Required for current Google Play submission policy |
| Scripting Backend | IL2CPP        | Release builds only; Mono permitted for local dev editor builds |
| Architecture     | ARM64 + ARMv7 | 64-bit required for Play Store; fat binary for device coverage |

Raising minSdk reduces device reach; lowering targetSdk may block store submission. Both require a TASKS.md entry with justification and owner approval.

## 3. iOS Deployment Target

**Pinned: iOS 15.0**

- Covers ~99% of active iPhones as of 2026.
- Required for Metal shaders, App Tracking Transparency (ATT), and async/await Swift interop.
- Lowering below 15.0 is not permitted without owner approval; raising is permitted with test evidence.

## 4. EDM4U (External Dependency Manager for Unity) Policy

EDM4U version is pinned to whatever is manually installed in `Packages/com.google.external-dependency-manager/`.

**Rules:**
- Auto-update is DISABLED. EDM4U must never be set to auto-resolve on import without explicit review.
- Version bumps require a TASKS.md entry listing the before/after version, the reason, and evidence that CocoaPods integration still builds.
- EDM4U Android resolver settings must be committed to `ProjectSettings/`; they must not be left at defaults.
- Do not use EDM4U to pull transitive SDKs that are not explicitly approved in `TASKS.md` (see ENG-M13-003).

---

## 5. CocoaPods Version Expectations

- CocoaPods is consumed indirectly via EDM4U on the CI or developer's macOS machine.
- Expected version: **>= 1.14.0** (supports Xcode 15+ xcframework packaging).
- The `Podfile` generated by EDM4U is not committed; it is regenerated by EDM4U on each build.
- If a CocoaPods dependency conflicts with a pinned pod version, the resolution is: **add a `podfile_properties.json` override** via EDM4U settings — do not pin pods directly in hand-written Podfile fragments without a TASKS.md entry.

## 6. IL2CPP vs Mono Scripting Backend

| Build type         | Required backend | Reason                                    |
|--------------------|------------------|-------------------------------------------|
| Release (Android)  | IL2CPP           | Required for 64-bit Play Store + stripping |
| Release (iOS)      | IL2CPP           | Apple requires AOT compilation            |
| Local dev (Editor) | Mono             | Faster iteration; IL2CPP not needed       |
| CI test builds     | Mono preferred   | Speed; IL2CPP only if testing strip/link  |

IL2CPP requires the IL2CPP build support module to be installed in Unity Hub. Switching backends in ProjectSettings/ProjectSettings.asset requires a TASKS.md entry if committed to source control.

## 7. Downgrade Procedure

If a Unity version upgrade must be reverted:

1. **Record the current state:** note failing commit SHA, broken package versions, symptom.
2. **Revert Unity Hub installation:** install the pinned version (6000.6.5f1) from Unity Hub's install archive. Do not uninstall the newer version until the downgrade is verified — keep both installs temporarily.
3. **Reopen the project** in the pinned version. If Unity prompts to upgrade project assets, **decline** and open in safe mode if available.
4. **Re-run the full test suite** (all EditMode and Runtime tests). All tests that passed at the previous pinned version must pass again.
5. **Record evidence** in a TASKS.md entry: before SHA, after SHA, failing test names (if any), test run output summary.
6. **Do not merge the downgrade commit** until a separate reviewer confirms the test suite passes.

## 8. Change-Control Procedure for SDK Version Changes

Any change to a pinned SDK version (Unity, Android SDK, iOS deployment target, EDM4U, or any explicitly versioned Unity package) requires:

1. A new TASKS.md entry (or amendment to an existing one) containing:
   - **Before:** current pinned version + HEAD SHA at time of change.
   - **After:** proposed version + rationale (security patch, store requirement, feature need).
   - **Risk assessment:** which five games are potentially affected.
   - **Test evidence:** test suite output before and after the change.
   - **Owner approval required:** YES for major version bumps (e.g. Unity 6 → Unity 7, Android minSdk bump, iOS deployment target change). Category C gate.
   - **Owner approval required:** NO for patch-level fixes if tests all pass and no game behavior changes — but a TASKS.md entry is still required.

2. The change must be committed with `[skip ci]` per project rules (no paid CI).

3. A QA agent must independently verify the change before the TASKS.md status advances past `IMPLEMENTED_UNAUDITED`.

## 9. EDM4U / CocoaPods / IL2CPP Conflict Matrix

| Conflict scenario | Resolution |
|---|---|
| EDM4U auto-resolves a newer pod that breaks IL2CPP stripping | Pin the pod version in `podfile_properties.json`; file TASKS.md entry |
| CocoaPods < 1.14 produces xcframework errors | Upgrade CocoaPods on the build machine; document in TASKS.md |
| IL2CPP and Mono produce different behavior for reflection | Mark the code path with `// ponytail: IL2CPP reflection limit`; add IL2CPP-specific test |
| EDM4U pulls in Firebase SDK not approved in ENG-M13-003 | Remove from EDM4U dependencies.xml; file blocking TASKS.md entry for ENG-M13-003 approval |
