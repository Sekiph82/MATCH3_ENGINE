# Unity batch validation and release content firewall

Run the local Windows validation adapter with PowerShell 7:

```powershell
pwsh -NoProfile -File Tools/RunUnityCI.ps1 -ProjectPath . -EditorPath 'C:\Program Files\Unity\Hub\Editor\6000.6.5f1\Editor\Unity.exe'
```

It executes EditMode and PlayMode through Unity batchmode, runs the release-scanner, SDK-pin, Unity-bootstrap, and repository-policy positive/negative fixtures, validates the pinned provenance records, and propagates child nonzero exit codes. Each Unity run writes its NUnit XML and Editor log to a unique directory under the system temporary path. Any failed, skipped, inconclusive-only, or empty required suite fails closed. `-EvidenceDirectory <path>` places raw logs/XML at a chosen evidence root.

To scan a release output directory or ZIP-based `.apk`, `.aab`, `.ipa`, `.zip`, or `.unitypackage`, pass `-ArtifactPath <path>`. The scanner checks entry paths, assembly names, scripts and fixtures in Resources/StreamingAssets/Addressables, and embedded test-runner/test-assembly markers. It does not extract archives. Payload entries over 256 MiB fail closed when content cannot be inspected.

Before building a player, run `pwsh -NoProfile -File Tools/ScanUnityReleaseArtifact.ps1 -SourceAssetRoot Assets -ManifestPath <evidence-directory>/prebuild-source-assets.txt`. This enumerates every source asset, rejects developer-only resource families and opaque prebuilt `.bundle`, `.assetbundle`, or `.unity3d` inputs, and writes normalized source paths with SHA-256 and byte counts. The manual independent workflow runs this gate immediately before its Windows player build, then scans the built player and records the manifest with other raw evidence. If an additional source root feeds the build, it must also be supplied as `-SourceAssetRoot` before packaging.

Developer-only path families fail closed case-insensitively across slash styles: `StreamingAssets/Diagnostics/**`, `Addressables/Development/**`, `Resources/DeveloperLogs/**`, and explicit Factory tooling directories. Under `StreamingAssets/Factory`, filenames containing database, debug, or pipeline terms are rejected for tooling/data extensions (`.bytes`, `.db`, `.sqlite`, `.cache`, `.manifest`, `.output`, `.dat`, `.csv`, `.tsv`, `.json`, `.asset`, `.prefab`, `.txt`, `.log`, `.bin`, `.xml`, `.yaml`, `.yml`). Production visual formats `.png`, `.jpg`, `.jpeg`, `.webp`, `.tga`, and `.psd` remain allowed by that Factory filename rule, including themed Factory art; developer-only directory rules still take precedence.

Run `pwsh -NoProfile -File Tests/Policy/ReleaseArtifactScanner.Tests.ps1` for positive and negative scanner fixtures. Coverage keeps the three original R01 failures, adds all four R02 counterexamples, unknown suffix/prefix mutations, mixed-case and backslash paths, harmless text and binary payloads, multiple permitted Factory art files, ZIP plus ZIP-formatted `.apk`/`.aab`/`.ipa` path fixtures, and source-manifest positive/fail-closed behavior including rejection of opaque prebuilt bundle files. Those mobile-extension fixtures exercise archive path scanning only; they are not Android or iOS builds. The scanner does not introspect opaque Unity AssetBundle or encrypted bundle internals inside a built player/archive; such outputs must be produced from the hashed, validated source roots or excluded. The source preflight refuses opaque prebuilt bundle files whose contents cannot be tied to that manifest, and the documentation makes no claim that arbitrary bundle bytes were inspected.

## ENG-M00 R01 independent proof route

`.github/workflows/eng-m00-independent-runtime.yml` is manual-dispatch only. It is pinned to immutable checkout/upload action SHAs and the dispatch commit SHA. It requires a clean external runner labeled `independent-unity-6000.6.5f1` and `windows-build-support`, with Unity 6000.6.5f1, its existing license, and Windows player support already installed. The runner must be separate from the owner workstation and independently controlled. Configure the `m00-independent-runtime` GitHub Environment with a required reviewer before dispatch. The workflow does not download or activate Unity, install player modules, or use a GitHub-hosted runner.

When explicitly dispatched on that prepared runner, it exercises the intentional failing assertion and verifies the one-failed/zero-skipped/nonzero-exit result; runs the complete EditMode, PlayMode, and repository policy suites; imports the engine plus exact SDK/UniTask pins in a clean blank project; opens the immutable upstream sample and sends a real pointer-down/drag pair until an accepted match changes the board; creates the pre-build source asset manifest; and builds/scans the Windows player. Raw Editor logs, NUnit XML, resolved lockfile, source asset manifest, player scan, run metadata, and SHA-256 manifest are uploaded as a workflow artifact. The action is not dispatched by this repository change, and no CI execution is claimed until its run URL and uploaded raw result are available.

The local adapter remains builder-side evidence. Android/iOS package and device inspection remains pending platform modules and signing access; this scanner pass does not substitute for those checks. No hosted compute, Unity activation, or module installation was authorized or started for this R02 source change.
